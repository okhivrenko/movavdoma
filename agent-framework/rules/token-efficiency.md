# Token and Context Efficiency Rules

- Start with `rg` route maps and bounded file ranges.
- Load only the selected role, rule modules, project pointers, and workflow.
- Skip role, router, and workflow files for clear mechanical work already
  governed by root or nested project instructions.
- Give subagents compact task packets; avoid full-history forks by default.
- Return distilled evidence with file references instead of raw file dumps,
  test logs, or repeated background.
- Reuse established route maps and decisions within the same objective.
- Run focused checks after a slice and the full required suite at its gate.
- Use one agent for sequential work and parallelize only independent latency.
- Use the lowest sufficient reasoning effort; raise it only for ambiguity,
  security, cross-system risk, or failed verification.
- Treat role activation and agent spawning separately. The primary agent may
  apply several role gates sequentially without creating extra sessions.
- For a selected skill, read `SKILL.md` first and no more than two references on
  the first pass. Never load a compiled reference when focused files exist.
- Keep subagent task packets under roughly 250 words and ask for a bounded
  summary rather than a transcript.
- Compact or start a new coherent thread when context no longer serves the
  current outcome.
